The point

A repo that knows you

You work across multiple projects. Each one starts fresh — Claude doesn't know what you decided last week, where your infra docs live, or that you prefer Postgres over Supabase.

LOS is one git repo that holds all of that. Your projects, your knowledge, your decisions, your daily logs. It lives on GitHub, you pull it anywhere, and any project can read from it or write back to it.

Connect any project to LOS by telling Claude where it lives, or drop a .claude.los file in the project root so it finds it automatically. Either way, Claude knows who you are, what you're working on, and where everything lives. Your context follows you.

And to be clear — LOS doesn't store passwords or API keys. It's markdown in a git repo. Store references to where secrets live, never the secrets themselves.

The engine

Task system is the special sauce

/task-system

This is what makes the whole thing evolve. The task system forces a loop: plan it, build it, verify it worked, write down what you learned. Every task goes through this, and the learnings accumulate in a knowledge file that informs the next task.

plan → build → verify → fix → learn

It works in gated mode (you approve each step) or loop mode (Claude runs autonomously — plan to build to verify to learn — and only stops when it's stuck or done). Loop mode is what lets you say "handle it" and walk away.

If verify fails, it tries to fix. If two fixes fail, it stops and waits for you. It never spins. And because every task is one file — the analysis, the plan, the work log, the test results, the learnings — you can pick up any task months later and see exactly what happened.

This works on LOS itself and on any connected project. Say "start session" in your API repo and the task system runs there, logging progress back to LOS. One workflow across all your work.

Docs

How it actually works

Everything you need to understand LOS. Concepts, then common questions.

Concepts

Loop mode

This is LOS's most powerful feature. Say "loop it" and Claude runs autonomously through the full task lifecycle — plan, build, verify, learn — without stopping to ask for approval.

Auto-advance

Plan → build → verify → learn → close. Each phase triggers the next automatically.

Self-correcting

If verify fails, it tries to fix. If two fixes fail, it stops and asks you. It never spins forever.

Safe boundaries

New tasks always need one human plan approval. After that, loop takes over. STUCK and BLOCKED always stop.

Walk away

Say "handle it" and go do something else. Claude works until it's done, stuck, or blocked. You come back to results.

Loop mode works because every task is a file with strict phases. Claude can't skip steps or go in circles — the system constrains it. The constraint is what makes autonomy safe.

Memory system

Everything Claude needs to know about you and your work lives in memory/. It's just folders and markdown files.

  • memory/identity.md — your name, role, goal, current state. Survives every update.
  • memory/projects/ — one folder per project with a readme, tasks, and decision log.
  • memory/knowledge/ — everything you've learned — topics, life areas, ingested sources. One flat folder, no taxonomy overhead.

Memory is yours and untouchable. Updates replace system files but never touch memory/. It's the one folder that grows over time and never resets.

Skills

A skill is a SKILL.md file in .claude/skills/. It tells Claude what to do when you say certain things. Each skill declares its own triggers — there's no central routing table to maintain.

LOS ships with 6 core skills: task-system, learn, build-project, evolve, create-skill, and update-los. But you can create your own. Say "create skill for code review" and Claude writes a new skill file. It works on the next message.

Design skills to be portable. A skill you write in LOS can be copied into any project. The task system, for example, works in any repo — just drop the skill folder in and say "start session". We highly recommend taking it with you to every project.

You can also ask Claude inside a project to create a project-specific skill based on one you already have in LOS. Your LOS skills become templates for the rest of your work.

Skills you create are never overwritten by updates. Only skills marked LOS:managed get replaced — your custom ones are yours.

CLAUDE.md

The orchestration file. It's what Claude reads first when you open a session. It contains your onboarding flow, autonomy rules, system rules, and self-healing checks.

It does not contain your identity or a list of skills. Identity lives in memory/identity.md. Skills are discovered automatically from .claude/skills/. This means CLAUDE.md is fully replaceable — updates swap it out without losing anything personal.

Updates

Say "update los" and Claude checks GitHub for a newer version of the template. It shows you what changed, and if you approve, it replaces system files.

The rule is simple: any file with a LOS:managed marker gets replaced. Everything else is untouched. Your memory, tasks, logs, and custom skills are safe. If something goes wrong, it's all in git — one git checkout undoes any file.

Cross-project

Tell Claude where your LOS lives, or drop a .claude.los file in any project root so it finds it automatically. Either way, Claude reads your LOS for context — who you are, what you know, what you decided — without you repeating anything.

Tasks can target other repos too. Plan a task in LOS, set target_repo, and the system hands it off to the right place for building. Plan where you have context. Build where the code lives.

FAQ
Does LOS store passwords or API keys?

No. LOS stores references to where your secrets live ("AWS creds: vault X", "SSH key: path Y") but never the secrets themselves. It's markdown files in a git repo — don't put anything sensitive in them.

What do I need to run this?

Git and Claude Code (the CLI). That's it. No npm, no Python, no Docker. Clone the repo, run claude, answer three onboarding questions.

Can I use this with an existing project?

Yes. Just tell Claude where your LOS directory is, or create a .claude.los file in your project root for automatic discovery. The project keeps its own code and git history — LOS just provides the context layer.

What happens if an update breaks something?

Everything is in git. Run git diff to see what changed, git checkout -- filename to revert any file. Updates only touch files marked LOS:managed — your data is never at risk.

Can two people share a LOS?

Yes. It's a git repo. Push and pull as usual. Projects, decisions, task history, and knowledge are shared. Each person's sessions add to the same logs. Works well for pairs or small teams.

How is this different from a notes app?

A notes app stores text. LOS stores text and acts on it. Your projects, knowledge, and decisions aren't just files — they're context that Claude reads and uses. Say "start session" and it knows your active task, what failed last time, and what to try next. The files are the database and the AI reads them as instructions.

What if I want a skill LOS doesn't have?

Say "create skill for [whatever]". Claude writes a SKILL.md file, and it works immediately. Your custom skills survive updates. Some examples people have built: deploy checklist, code review, daily standup summary, meeting notes formatter.

Is loop mode safe? Can Claude go rogue?

Loop mode has hard constraints. It must follow strict phases (plan → build → verify). It can't skip verification. After two failed fixes it stops automatically (STUCK). It can't proceed past BLOCKED status. And new tasks always require one human plan approval before loop mode kicks in. The autonomy is real, but bounded.
