LOS
Life Operating System

A folder of markdown files and Claude Code skills that keep your projects, notes, and tasks in one place.

$ git clone los-starter
$ cd los-starter && claude
> "start session" # that's it
Skills

What you can say

Claude picks the right skill from how you phrase things. Or type the slash command directly.

/learn

Say "learn OAuth" and you get a file in memory/knowledge/ with the core ideas, the parts that trip people up, and links that are actually worth reading.

"learn oauth" · "research k8s networking"
/build-project

Creates a project folder with a readme, a task list, and a decision log. Checks if one already exists first.

"new project my-api" · "build dashboard"
/task-system

Picks one task, plans it from three angles (analyst, architect, PM), builds it, verifies it works, and writes down what you learned before archiving.

"start session" · "new task" · "what's next"
/evolve

Checks your system for problems — stale projects, missing files, gaps in your logs — and fixes what it can.

"review" · "status" · "health check"
/create-skill

Describe what you want automated. Claude writes the skill file, adds routing to CLAUDE.md, and it works on the next message.

"create skill for deploys" · "new skill"
Setup

Three commands

1

Clone it

Grab this repo. It's just folders and markdown — nothing to install or compile.

2

Run claude

Claude reads CLAUDE.md at startup and loads every skill in .claude/skills/. That's the whole config.

3

Just talk

Say what you want. "learn Docker", "new project", "review". The routing table in CLAUDE.md handles the rest.

Structure

What's in the folder

CLAUDE.md ............. routing + rules
.claude/skills/ ....... the 6 skills
memory/
  projects/ ............ one folder per project
  knowledge/ ........... what you've learned
  areas/ ............... career, health, whatever
  decisions/ ........... choices you've made
logs/ .................. one file per day
.tasks/ ................ shows up when you start one
.claude.los ............ drop into other repos
Ideas

Why it works this way

Everything in one place

A task doesn't end up in Notion while its notes live in Google Docs and the decision is buried in Slack. One folder. One system.

Behavior lives in markdown

Each skill is a markdown file that tells Claude what to do. Change the file, change the behavior. No code, no deploy.

Catches your blind spots

/evolve notices things you forgot — a project with no readme, three days with no log entry, a knowledge file that's gone stale.

Connects your repos

Drop .claude.los into a project and Claude knows about your other work. Finish a deploy, it logs back to LOS automatically.

You own all of it

No account. No sync service. No vendor lock-in. It's markdown in a git repo. If you stop using it, the files are still readable.

Grows by talking

Need a skill that doesn't exist? Describe it. Claude writes the skill file, wires it up, and it works next time you ask.
